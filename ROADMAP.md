# Штаб.AI — дорожная карта дистрибутива

Текущий этап: чистая установка и проверка на реальном оборудовании. Основная версия — `main`; четыре публичных скрипта установки/удаления описаны в [README](README.md).

## Системные требования для тестовой версии

Это требования текущего установщика, а не обещание одинаковой скорости на всех компьютерах. Производительность проверяем на реальных записях.

| Параметр | Windows | Ubuntu |
|---|---|---|
| ОС | Windows 10 22H2 или Windows 11, x64; Home / Pro. Рекомендуется Windows 11 | Ubuntu 24.04 LTS, x64 |
| Процессор | Intel/AMD, минимум 4 логических ядра | Intel/AMD, минимум 4 доступных ядра |
| RAM: минимум | 16 ГБ в компьютере; WSL должен предоставлять приложению не менее 10 ГБ | Не менее 10 ГБ памяти, видимой системе; учитывайте потребление других приложений |
| RAM: рекомендуется | 24 ГБ и более | 16–24 ГБ и более |
| Свободное место: минимум | 40 ГиБ на выбранном диске установки, включая скачивание архивов | 30 ГиБ на выбранном разделе; отдельно место для общих Docker-образов, записей и резервных копий |
| Накопитель | Рекомендуется SSD | Рекомендуется SSD |
| Права | Администратор Windows | `sudo` / root |
| Виртуализация | Включена в BIOS/UEFI; WSL2, VirtualMachinePlatform, systemd внутри WSL | Для установки непосредственно на Ubuntu виртуализация не требуется |
| Интернет | При установке: GitHub, Ubuntu, репозитории пакетов, Ollama и Hugging Face | При установке: GitHub, репозитории пакетов, Docker, Ollama и Hugging Face |
| Интерфейс | Браузер с поддержкой современного JavaScript, HTTPS и загрузки файлов | То же; графический рабочий стол нужен только для ярлыков |

Память и диск сверх минимума нужны для одновременной работы с другими программами, хранения записей и резервных копий. Размер этих данных не ограничивается указанным запасом места.

Windows Server, ARM и 32-разрядные ОС в этом комплекте не поддерживаются. Полный компонент Hyper-V, отдельная Hyper-V VM и Docker Desktop не требуются. WSL2 использует системную виртуализацию. После включения компонентов может потребоваться перезагрузка и повторный запуск того же установщика.

## Режимы оборудования

| Режим | Windows | Ubuntu | Условия |
|---|---|---|---|
| CPU | Нативная Ollama; Whisper CPU в WSL | Ollama CPU; Whisper CPU в Docker | Видеокарта не обязательна. Скорость зависит от CPU и памяти |
| NVIDIA | Нативная Ollama GPU; Whisper CUDA в WSL | Ollama GPU; Whisper CUDA в Docker | Поддерживаемая CUDA-карта, установленный драйвер; в Windows — CUDA в WSL. NVIDIA Container Toolkit устанавливается скриптом |
| AMD Radeon | Нативная Ollama ROCm; Whisper CPU | Ollama ROCm; Whisper CPU в Docker | Карта из списка поддержки Ollama для выбранной ОС; в Ubuntu — ROCm-драйвер и `/dev/kfd`, `/dev/dri` |

Для тестов с GPU рекомендуется **8 ГБ VRAM и более**. Это ориентир, а не универсальный минимальный порог: расход памяти зависит от модели, контекста и одновременных задач. На NVIDIA память используют и Ollama, и Whisper. Возможность частичного размещения Ollama на CPU не гарантирует, что Whisper CUDA поместится в оставшуюся VRAM.

Драйвер видеокарты подготовьте до установки. Проверка GPU делает короткий реальный запрос к модели; если выбран GPU, а Ollama целиком работает на CPU, установщик сообщает ошибку. Карты вне поддерживаемого списка можно тестировать в режиме CPU. Intel GPU, экспериментальный Vulkan и ASIC в текущем комплекте не заявлены.

Списки совместимости: [Ollama GPU](https://docs.ollama.com/gpu), [NVIDIA CUDA on WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html). Совместимость проверяйте для конкретной модели карты и установленного драйвера, а не только по названию производителя.

## Сеть и резервные копии

Место установки выбирается в установщике. Windows: новая папка на локальном фиксированном NTFS-диске (`-InstallDir`). Ubuntu: новая папка на постоянно смонтированном ext4/xfs/btrfs-разделе; приложение и содержимое Docker-томов размещаются там, `/opt/shtab-ai-021` остаётся служебной bind-привязкой. Общие образы и кэш Docker автоматически не переносятся. Для нестандартной папки резервные копии располагаются рядом с суффиксом `-Backups` (Windows) или `-backups` (Ubuntu), вне удаляемого каталога. Подробности и примеры — в [README](README.md).

- Локальный доступ: Windows — `https://localhost:8445/login`; Ubuntu — `https://localhost/login`.
- Для LAN закрепите IPv4 адрес компьютера. Windows использует TCP 8445 в Private/Domain сети; Ubuntu — TCP 443 и 80 на выбранном интерфейсе. Разрешён доступ из локальной подсети. Публикация в Интернет не входит в текущую схему.
- На клиентских компьютерах добавьте публичный корневой сертификат приложения в доверенные. Успешная локальная проверка не подтверждает работу браузера и файерволла другого ПК.
- При стандартном пути Windows-бэкапы сохраняются в `Документы\ShtabAI-Backups`, Ubuntu-бэкапы — в `/var/backups/shtab-ai-021`; при другом пути — рядом с папкой установки, вне неё. Выделите место для основной и страховочной копии; эти папки сохраняются после удаления приложения.
- Для защиты от потери диска копируйте резервные копии на отдельный носитель. Копии содержат данные и секреты приложения.


## Windows: частная сеть и антивирус

- [ ] **Частная сеть.** Перед включением доступа из локальной сети показать выбранный адаптер, IPv4 и профиль сети. Для профиля «Общедоступная» дать понятный переход к настройкам Windows; смену на «Частная» выполняет пользователь только для доверенной домашней или офисной сети. Проверить доступ с другого ПК, сохранение правил после перезагрузки и отказ в доступе из посторонней подсети.
- [ ] **Антивирус.** Проверить полный цикл с включённым Kaspersky Plus: установка, загрузка компонентов и моделей, HTTPS, создание администратора, автозапуск и обработка записи. Зафиксировать версии Windows/WSL/Kaspersky и точный отчёт обнаружения. Срабатывание `PDM:Trojan.Win32.Generic` на CMD-обёртке от 09.10.2026 пока не устранено подтверждённым тестом. При подозрении на ложное срабатывание подготовить обращение в Kaspersky; подпись установщика и её влияние требуют отдельной проверки.
- [ ] **Установка при блокировке антивирусом — два предусмотренных варианта.** (1) Пользователь вручную приостанавливает защиту на время установки, затем включает её и проверяет запуск и обработку записи. (2) Пользователь задаёт точечные исключения или правила доверия для проверенных файлов установщика и компонентов. Определить минимальный необходимый набор по отчёту Kaspersky и проверить его; исключение всего PowerShell, системного диска или всех загрузок не использовать как стандартную инструкцию. В установщике дать понятную подсказку; автоматическое отключение защиты не выполнять. Перед передачей дистрибутива пользователям проверить оба сценария на реальном оборудовании.

## Ближайшие проверки

1. Чистая установка Windows и Ubuntu в режиме CPU: зависимости, скачивание моделей, создание администратора, ярлыки приложения и диспетчера.
2. Чистая установка NVIDIA и AMD на поддерживаемых картах; проверка фактического ускорения и записи RAM/VRAM, времени распознавания и генерации.
3. Вход и загрузка записи с другого ПК: сертификаты, правила сети, ограничения локальной подсети.
4. Перезагрузка компьютера; запуск и остановка через диспетчер, восстановление доступа без ручного исправления адреса WSL.
5. Резервная копия, проверка целостности, восстановление и проверка входа/записей после восстановления.
6. Полное удаление и новая установка; проверка сохранности бэкапов и отсутствия ресурсов прежней установки.
7. Проверка прогресса Яндекс.Диска и итогового времени на реальной загрузке.
8. Установка на другой диск/раздел, перезагрузка, обслуживание и полное удаление; сохранность копий и отказ при недоступности выбранного диска.

По результатам этих тестов уточняем рекомендации по оборудованию и исправляем установщик. Автоматические проверки уже проходят; перечисленные аппаратные и сетевые проверки пока не считаются выполненными.


## Автоматизация сетевого адреса и прогресс моделей — 09.10.2026

- Реализовано: адрес выбранного Windows-адаптера читается при запуске и каждые 15 секунд; при смене IPv4 обновляются portproxy, правило Windows Firewall, адрес HTTPS и разрешённые хосты. Выбранный адаптер сохраняется по GUID. При отключении адаптера или общедоступном профиле остаётся локальный доступ. Существующий корневой сертификат сохраняется. Изменения окружения применяются после завершения установки; при ошибке перезапуска контейнеров предусмотрена повторная попытка.
- Реализовано: Qwen показывает байты текущего слоя из потока Ollama; Whisper показывает размер полученных файлов и общий объём из метаданных закреплённой версии модели. Скорость и время рассчитываются по новым данным; старые сведения не используются для оценки времени.
- [ ] Проверить на реальном Windows-компьютере: смена DHCP-адреса, перезагрузка, отключение сети, вход с другого ПК по новому адресу, загрузка Whisper после обрыва и работа с включённым Kaspersky. Автоматические тесты не заменяют эту проверку.

## Диагностика GPU и повторная чистая установка — 09.10.2026

- Реализовано: автоматический предварительный выбор CPU/NVIDIA/AMD; точные названия карт, CUDA compute capability, версия NVIDIA-драйвера и доступная выделенная видеопамять. Список AMD относится к Windows ROCm, а не Linux. Снимок требований: https://docs.ollama.com/gpu (09.10.2026). Порог 4096 МБ свободной NVIDIA VRAM — консервативная политика установщика, не опубликованный минимум Qwen или Whisper.
- Реализовано: Qwen выполняет пробный запрос и проверяет фактическую GPU-память модели. При неподтверждённом GPU native Ollama перезапускается в режиме CPU, режим сохраняется; успешный запуск Qwen на CPU больше не обрывает установку. Whisper выполняет короткое распознавание, включая ленивое выполнение генератора; при ошибке CUDA повторяет проверку на CPU. Ошибка, которая повторяется на CPU, остаётся ошибкой установки. CPU-настройки Whisper сохраняются отдельно.
- Реализовано: выбранный сетевой интерфейс и профиль показываются до настройки LAN; общедоступный профиль меняется на частный только после явного ответа пользователя. Установщик показывает обнаруженные антивирусы и два ручных варианта при блокировке: временная приостановка либо точечные исключения. Ложное срабатывание Kaspersky пока не проверено на реальном оборудовании.
- Реализовано: Cleanup-ShtabAI-RU.ps1 удаляет проверенную установку ShtabAI-021 и её дистрибутив WSL, модели, задачи, правила и собственный сертификат. При отсутствии других дистрибутивов выполняет удаление общего WSL. Резервные копии сохраняются по умолчанию; отдельный параметр RemoveBackups удаляет только проверенную именованную папку. Журналы сохраняются для разбора ошибок. Переходы по junction/symlink за пределы установки исключены.
