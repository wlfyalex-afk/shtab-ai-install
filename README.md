# Штаб.AI — установка на Windows и Ubuntu

Основной дистрибутив находится в `main`. Для Windows скачайте только **Start-ShtabAI-Windows.cmd** и запустите его двойным щелчком. Другие файлы вручную скачивать не нужно. Для Ubuntu выберите соответствующий скрипт из таблицы:

| ОС | Установка | Полное удаление |
|---|---|---|
| Windows Home / Pro | [Install-ShtabAI-Windows.ps1](Install-ShtabAI-Windows.ps1) | [Uninstall-ShtabAI-Windows.ps1](Uninstall-ShtabAI-Windows.ps1) |
| Ubuntu | [Install-ShtabAI-Ubuntu.sh](Install-ShtabAI-Ubuntu.sh) | [Uninstall-ShtabAI-Ubuntu.sh](Uninstall-ShtabAI-Ubuntu.sh) |

Для Windows доступно меню в одном файле: [Start-ShtabAI-Windows.cmd](https://raw.githubusercontent.com/wlfyalex-afk/shtab-ai-install/main/Start-ShtabAI-Windows.cmd). Сохраните файл и запустите двойным щелчком: **1** — установка с выбором папки, CPU/GPU и доступа по сети, **2** — удаление выбранной установки, **0** — выход. Меню, вопросы и сообщения установщика отображаются по-русски. Файл скачивает актуальные скрипты; требуется интернет. Если WSL отсутствует или встроенная версия устарела, установщик скачивает официальный MSI WSL из Microsoft/WSL и проверяет подпись Microsoft. Перезагрузите Windows по сообщению установщика и снова выберите **1**. Удаление сохраняет WSL и другие приложения; перед удалением данных требуется явное подтверждение.


Загрузчик Windows автоматически скачивает из одной зафиксированной версии GitHub:

| Файл | Назначение |
|---|---|
| `Install-ShtabAI-Windows.ps1` | Запуск установки и запрос прав администратора |
| `SHA256SUMS` | Проверка загруженных файлов |
| `windows/Install-WSL.ps1` | Установка WSL и приложения |
| `windows/Test-ShtabGPU.ps1` | Проверка совместимости видеокарты |
| `windows/Install-Progress.ps1` | 17 этапов установки, проценты, скорость и время загрузки |
| `windows/Download-Cache.ps1` | Проверка и повторное использование архивов и моделей из кэша |

Все служебные скрипты из `windows/` сохраняются рядом и проверяются до запуска установки. Затем установщик скачивает полный архив этой же версии репозитория с приложением и служебными файлами, включая `windows/Start-ShtabRuntime.ps1` и `windows/Manage-ShtabAI.ps1`. Отсутствие файла, ошибка скачивания или несовпадение контрольной суммы останавливает запуск с указанием проблемного файла.

Установщик предлагает процессор Intel/AMD, NVIDIA или AMD Radeon; локальный доступ или доступ из локальной сети. Затем скачивает компоненты и модели, проверяет их, предлагает создать первого администратора и создаёт ярлыки приложения и диспетчера. Интернет нужен при установке. Модели Qwen3 4B и Whisper large-v3-turbo выполняются на вашем компьютере.

Сводный индикатор показывает этапы установки, ниже обновляется текущая операция.
Проценты загрузки обновляются на месте. При сборке образа показаны загрузка слоёв
Python, установка ffmpeg и библиотек либо сохранение образа. Процент текущего
слоя отображается при известном объёме; для установки пакетов точного процента нет.
Подробные сообщения сохраняются в журнале. Закрытие окна прогресса не останавливает
фоновую установку. Для повторного теста с нуля используйте пункт **2 — Удалить**
в Windows CMD, затем **1 — Установить** и выберите прежнюю отдельную папку
**Shtab.AI-Cache** — она сохраняется при удалении приложения.

## Поддержка и журналы

По вопросам установки и работы приложения: **[wlfyalex@gmail.com](mailto:wlfyalex@gmail.com)**.
На первом этапе достаточно письма с **журналом и скриншотом ошибки**.
Укажите Windows или Ubuntu и её версию, что вы делали и на каком этапе возникла
ошибка. Снимок должен показывать текст ошибки и номер этапа, если он есть.
Перед отправкой проверьте, что на снимке и в журнале нет паролей или данных,
которые вы не хотите передавать.

### Windows

Если запускали **`Install-ShtabAI-RU.ps1`**, журнал `ShtabAI-install-ДАТА-ВРЕМЯ.log`
создаётся **рядом с этим скриптом**, например в `D:\Temp`. В конце установщик
показывает полный путь к журналу. После повторных запусков приложите журнал
той попытки, в которой возникла ошибка.

При запуске через **`Start-ShtabAI-Windows.cmd`** журналы автоматически создаются
в **`%LOCALAPPDATA%\ShtabAI\Logs`**:

* `ShtabAI-bootstrap-*.log` — запуск меню и скачивание установщика, включая
  ошибки до его загрузки;
* `ShtabAI-install-*.log` — установка, проверка Windows/WSL и дальнейшие этапы.

Путь выводится в окне. После запроса прав администратора может появиться ещё
один журнал: это журнал установки в новом окне. Для обращения приложите последние
журналы запуска и установки с временем проблемной попытки. Чтобы открыть папку,
нажмите **Win+R**, введите `%LOCALAPPDATA%\ShtabAI\Logs` и нажмите Enter.

Если устанавливался Microsoft WSL через MSI, его дополнительный журнал находится
в `%TEMP%` и имеет имя `ShtabAI-WSL-MSI-*.log`; точный путь выводит установщик.
Журналы не удаляются вместе с приложением. При перезагрузке следующий запуск
создаёт новые файлы, предыдущие сохраняются.

**Для ошибки при работе приложения:** откройте ярлык **`ShtabAI-021-Manager`**
и выберите **8 — Сохранить диагностику для поддержки**. На рабочем столе в папке
**`ShtabAI-support`** появится файл **`ShtabAI-diagnostics-*.txt`**. В нём версии
Windows и WSL, память и свободное место, состояние автозапуска и контейнеров,
последние журналы установки, приложения и Windows Ollama. Если часть сервисов
недоступна, причина попадёт в отчёт; остальные проверки продолжатся. Приложите
этот файл и скриншот к письму поддержки. Сбор не останавливает приложение и не
передаёт отчёт автоматически.

Ручной способ сохранения журналов, если диспетчер недоступен:

Если Linux-среда уже создана, сохраните журнал установки приложения. Откройте
**PowerShell под тем же пользователем Windows, который устанавливал Штаб.AI**,
и выполните:

```powershell
$folder = Join-Path ([Environment]::GetFolderPath('Desktop')) 'ShtabAI-support'
New-Item -ItemType Directory -Path $folder -Force | Out-Null
wsl.exe -d ShtabAI-021 -u root --exec journalctl -u shtab-ai-install -n 500 --no-pager 2>&1 | Out-File -LiteralPath (Join-Path $folder 'ShtabAI-install.log') -Encoding utf8
```

Если ошибка возникла **во время работы приложения**, в том же окне выполните:

```powershell
wsl.exe -d ShtabAI-021 -u root --exec /bin/bash -lc 'cd /opt/shtab-ai-021 && bash scripts/dc.sh logs --no-color --since 2h --tail 300 web meeting-worker llm-worker brief-worker proxy' 2>&1 | Out-File -LiteralPath (Join-Path $folder 'ShtabAI-app.log') -Encoding utf8
```

Файлы появятся в папке **`ShtabAI-support` на рабочем столе**. Команда для работы
приложения сохраняет последние сообщения за два часа; выполните её сразу после
ошибки. При проблеме запуска или работы Qwen также приложите существующие
`runtime-error.log`, `ollama-error.log` и `ollama.log` **из выбранной папки
установки Штаб.AI** (например `D:\Apps\ShtabAI-021`). Эти файлы появляются по
мере работы; отсутствие одного из них само по себе не является ошибкой.

Если команда сообщает, что WSL или дистрибутив `ShtabAI-021` не найден,
приложите этот текст и скриншот исходной ошибки. Не удаляйте установку перед
сохранением журналов.

### Ubuntu

Для ошибки при работе приложения откройте **`ShtabAI-Manager`**, выберите
**15 — Сохранить диагностику для поддержки**. То же действие из терминала:

```bash
sudo /opt/shtab-ai-021/shtabctl support
```

Файл **`ShtabAI-diagnostics-*.txt`** сохраняется в **`ShtabAI-support` внутри
домашней папки пользователя**, запустившего `sudo`. Отчёт доступен этому
пользователю и включает состояние сервисов, память, свободное место и последние
журналы. Он не копирует `.env`, пароли подключения, базу, записи или стенограммы.
Просмотрите файл перед отправкой: сообщения сервисов могут содержать рабочие
данные. Отчёт отправляется пользователем вместе со скриншотом на
**wlfyalex@gmail.com**.

Если установка ещё не завершена и меню недоступно, журналы можно сохранить
вручную. Откройте терминал. Для журнала установки выполните:

```bash
mkdir -p "$HOME/ShtabAI-support"
sudo journalctl -u shtab-ai-install -n 500 --no-pager > "$HOME/ShtabAI-support/ShtabAI-install.log" 2>&1
```

Для ошибки **во время работы приложения** дополнительно выполните:

```bash
sudo bash /opt/shtab-ai-021/scripts/dc.sh logs --no-color --since 2h --tail 300 web meeting-worker llm-worker brief-worker proxy > "$HOME/ShtabAI-support/ShtabAI-app.log" 2>&1
```

При проблеме Qwen на Ubuntu сохраните также журнал Ollama:

```bash
sudo bash /opt/shtab-ai-021/scripts/dc.sh logs --no-color --since 2h --tail 300 ollama > "$HOME/ShtabAI-support/ShtabAI-ollama.log" 2>&1
```

Файлы находятся в **`ShtabAI-support` внутри домашней папки пользователя**.
Сохраните их сразу после ошибки и отправьте вместе со скриншотом. Если установка
остановилась до создания службы `shtab-ai-install`, журнал этой службы ещё не
появится — в таком случае достаточно скриншота и текста ошибки из терминала.

## Требования

Подробная таблица требований, ограничения GPU и план чистого теста — в [дорожной карте](ROADMAP.md).

- Windows 10 22H2 x64 или Windows 11 x64; рекомендуется Windows 11. Home поддерживается. Не менее 12 ГБ RAM, рекомендуется 16–24 ГБ и более; 4 логических ядра, включённая виртуализация, минимум 40 ГиБ свободного места. Windows Server не поддерживается.
- Ubuntu **24.04 LTS x64**, не менее 10 ГБ доступной RAM, 4 ядер и 30 ГиБ свободного места на выбранном разделе; рекомендуется 16–24 ГБ RAM.
- Для GPU заранее установите актуальный драйвер производителя. Поддержка зависит от конкретной карты: [матрица Ollama](https://docs.ollama.com/gpu). NVIDIA в Windows должна поддерживать CUDA в WSL. AMD в Ubuntu требует поддерживаемого ROCm-драйвера и доступных `/dev/kfd`, `/dev/dri`.
- Для GPU рекомендуется 8 ГБ VRAM и более. При нехватке VRAM Ollama может частично использовать CPU; Whisper CUDA может потребовать освобождения памяти. Для неподдерживаемой карты выберите CPU.
- Запуск требует прав администратора. Компоненты WSL могут потребовать перезагрузку Windows; после неё повторите тот же файл.

Это кандидат для чистого эксперимента: автоматические проверки кода не заменяют установку и обработку записи на реальных Windows/NVIDIA/AMD.

На Windows с 12 ГБ RAM установщик задаёт WSL лимит 8 ГБ и swap 4 ГБ; Ollama работает в Windows. Это минимальный режим для тестирования: закройте тяжёлые приложения, обрабатывайте записи по одной. Полная установка и обработка на компьютере с 12 ГБ ещё требуют отдельного теста. Существующий пользовательский `.wslconfig` автоматически не заменяется.

Перед загрузкой Ubuntu установщик проверяет виртуализацию процессора и работающий гипервизор. Если виртуализация выключена в BIOS/UEFI, он выдаёт инструкцию и останавливается. Если запуск гипервизора отключён в настройках загрузки Windows, включает `hypervisorlaunchtype Auto` и просит перезагрузить компьютер. Изменение BIOS/UEFI выполняется пользователем.

## Windows: один файл

Установщик предложит папку установки. Можно выбрать другой локальный NTFS-диск, например `D:\Apps\ShtabAI-021`; папка должна быть новой. В ней будут WSL, Ollama, модели и данные. Путь можно передать явно:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-ShtabAI-Windows.ps1 -InstallDir 'D:\Apps\ShtabAI-021'
```

При нестандартном пути бэкапы размещаются рядом: `D:\Apps\ShtabAI-021-Backups`. При стандартном пути — в «Документах». Большие установочные архивы также скачиваются на выбранный диск; маленький стартовый скрипт, системные компоненты Windows/WSL и общий swap могут оставаться на системном диске. Скрипт удаления автоматически находит установку на другом диске.

Скачайте установщик по ссылке выше (кнопка **Raw → Save as**), затем в PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-ShtabAI-Windows.ps1
```

Или скачайте и запустите из PowerShell одной командой:

```powershell
& { $ErrorActionPreference='Stop'; [Net.ServicePointManager]::SecurityProtocol=[Net.SecurityProtocolType]::Tls12; Write-Host 'Downloading Shtab.AI installer...'; $p=Join-Path $env:TEMP 'Install-ShtabAI-Windows.ps1'; Invoke-WebRequest -UseBasicParsing -TimeoutSec 60 'https://raw.githubusercontent.com/wlfyalex-afk/shtab-ai-install/main/Install-ShtabAI-Windows.ps1' -OutFile $p; powershell.exe -NoProfile -ExecutionPolicy Bypass -File $p -KeepWindowOpen }
```

Будет создан собственный дистрибутив `ShtabAI-021` в WSL2. Docker работает внутри него; Docker Desktop и отдельная Hyper-V VM не нужны. WSL2 использует системную виртуализацию и компонент VirtualMachinePlatform, полный компонент Hyper-V не устанавливается. **Ollama работает нативно в Windows**, отдельно от WSL, и использует выбранный GPU. Установщик не подменяет другую установленную Ollama.

Приложение: `https://localhost:8445/login`. Диспетчер — ярлык `ShtabAI-021-Manager`. В нём доступны запуск/остановка, меню обслуживания, журналы, адрес сети и папка копий. Фоновая задача запускается при загрузке/входе; PowerShell запускается скрыто.

Бэкапы по умолчанию: `Документы\ShtabAI-Backups`; при выборе другой папки установки — рядом с ней, с суффиксом `-Backups`. Они сохраняются после удаления дистрибутива WSL. Архивы содержат данные и секреты приложения: храните их в защищённом месте.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall-ShtabAI-Windows.ps1
```

Удаление требует ввода `DELETE ShtabAI-021` и удаляет выбранную установку, модели, данные, задачу, собственные правила сети и ярлыки. Другие дистрибутивы, WSL и драйверы сохраняются. Автоматическая копия при полном удалении не создаётся.

## Ubuntu: один файл

Установщик выполняет системные действия с правами root. Его можно запускать из обычного терминала: скрипт сам вызывает `sudo` и продолжает установку с правами администратора. В уже открытой root-сессии (`sudo -i`) повторный `sudo` не нужен. Рекомендуется запуск от обычного пользователя, чтобы сохранить его имя в `SUDO_USER` для создания ярлыков; при прямом входе как root без `SUDO_USER` ярлыки пользователя не создаются. Бит выполнения не обязателен при запуске через `bash`.

Установщик предложит новую папку, например `/mnt/data/shtab-ai-021`. Раздел должен быть заранее смонтирован на постоянной основе через `/etc/fstab`, иметь файловую систему ext4/xfs/btrfs и не менее 30 ГиБ свободного места. Путь нужен абсолютный, без пробелов и символических ссылок. Можно передать его четвёртым аргументом:

```bash
bash Install-ShtabAI-Ubuntu.sh ask ask main /mnt/data/shtab-ai-021
```

Файлы приложения и содержимое всех четырёх Docker-томов будут на выбранном разделе. Для совместимости команд `/opt/shtab-ai-021` становится постоянной bind-привязкой к выбранной папке. Бэкапы хранятся рядом в `/mnt/data/shtab-ai-021-backups` и сохраняются при удалении. Для стандартного пути папка бэкапов остаётся `/var/backups/shtab-ai-021`.

Общие Docker-образы, кэш сборки и системные пакеты остаются в настроенном системном хранилище Docker; для них нужен дополнительный свободный объём (ориентир 8–12 ГиБ, зависит от режима GPU и кэша). Скрипт не переносит хранилище других Docker-приложений. Выбор папки применяется при новой установке; перенос существующей установки автоматически не выполняется.

Скачайте установщик и выполните:

```bash
bash Install-ShtabAI-Ubuntu.sh
```

Либо:

```bash
curl -fL https://raw.githubusercontent.com/wlfyalex-afk/shtab-ai-install/main/Install-ShtabAI-Ubuntu.sh -o Install-ShtabAI-Ubuntu.sh
bash Install-ShtabAI-Ubuntu.sh
```

Все сервисы, включая Ollama, работают в Docker. NVIDIA Container Toolkit устанавливается автоматически при выборе NVIDIA. Установщик не перезапускает Docker с чужими работающими контейнерами ради настройки GPU: в таком случае сначала подготовьте Toolkit. Драйвер видеокарты автоматически не заменяется.

Приложение: `https://localhost/login` при локальном режиме или `https://<IPv4 компьютера>/login` при сетевом. Ярлыки `ShtabAI` и `ShtabAI-Manager` создаются на рабочем столе пользователя, запустившего `sudo`; на машине без рабочего стола используйте `sudo /opt/shtab-ai-021/shtabctl menu`. GNOME может предложить разрешить запуск ярлыка.

Копии по умолчанию: `/var/backups/shtab-ai-021`; при выборе другой папки установки — рядом с ней, с суффиксом `-backups`. Диспетчер проверяет контрольные суммы, предлагает копию по номеру или пути, перед восстановлением создаёт страховочную копию. Восстановление переносит данные в текущую установку, сохраняя её сетевые настройки и секреты. Для переноса между ОС скопируйте каталог резервной копии в новую папку копий.

```bash
bash Uninstall-ShtabAI-Ubuntu.sh
```

Подтверждение: `DELETE-SHTAB-021`. Удаляются контейнеры, данные и модели именно проекта `shtab-ai-021`; копии, Docker и драйверы сохраняются.

## Ускорение

| Выбор | Windows | Ubuntu |
|---|---|---|
| CPU Intel/AMD | Нативная Ollama + Whisper CPU в WSL | Ollama CPU + Whisper CPU |
| NVIDIA | Нативная Ollama GPU + Whisper CUDA в WSL | Ollama GPU + Whisper CUDA |
| AMD Radeon | Нативная Ollama ROCm + Whisper CPU | Ollama ROCm + Whisper CPU |

Whisper использует faster-whisper/CTranslate2: этот движок поддерживает CUDA и CPU, поэтому AMD ускоряет языковую модель, а распознавание работает на CPU. ASIC исключены; Intel GPU и экспериментальный Vulkan не заявлены в этом дистрибутиве. Используются доступные процессорные ядра, GPU-режим проверяется реальным коротким запросом: если Ollama целиком осталась на CPU, установка выдаёт ошибку, а не сообщает об успешном GPU-ускорении.

## Доступ по сети

При выборе сети укажите активный IPv4 интерфейс. **Закрепите этот адрес в DHCP/роутере либо назначьте статический**: ярлыки, сертификат и правила используют выбранный адрес. При смене адреса потребуется перенастройка или чистая переустановка.

- Windows: входящий TCP 8445 разрешается из LocalSubnet для Private/Domain сети, проксируется в собственный WSL. Public сеть автоматически не переключается. Адрес WSL обновляется диспетчером при перезапуске.
- Ubuntu: TCP 443 и 80 публикуются только на выбранном IPv4; отдельная цепочка DOCKER-USER ограничивает источники выбранной подсетью, учитывая обход UFW опубликованными Docker-портами.
- PostgreSQL и API Ollama не публикуются в LAN. API нативной Windows Ollama разрешён только адресу собственного WSL.
- На каждом клиентском ПК импортируйте **публичный** `shtab-ai-root.crt` в доверенные корневые сертификаты. В Windows диспетчер показывает его путь; в Ubuntu — `/opt/shtab-ai-021/shtab-ai-root.crt`. Не передавайте `tls-data` или закрытые ключи.
- В установке проверяются HTTPS, сертификат и страница входа. Затем обязательно откройте URL с другого ПК и загрузите тестовую запись: локальная проверка не проверяет клиентские браузеры, межсетевые экраны и маршрутизаторы.

## Прогресс и проверка дистрибутива

Загрузка с Яндекс.Диска показывает прошедшее время ещё до первого полученного блока, затем скорость и оценку остатка. Сервер сообщает время текущей попытки и задержку heartbeat. Итоговая таблица относит `FETCHING` к загрузке, без двойного учёта в подготовке.

Установщики фиксируют SHA `main` перед скачиванием пакета и проверяют `SHA256SUMS`; Ubuntu-образ и нативные архивы Ollama также проверяются. Эти суммы проверяют целостность скачанного пакета, а не независимую подпись издателя.

Для разработки: `python -m unittest discover -s tests`, Bash/JavaScript синтаксис и PowerShell AST проверяются в GitHub Actions. Внутренние `install.sh`, `uninstall.sh`, `scripts/` и `windows/` обслуживают четыре публичных скрипта; запускать их отдельно пользователю не требуется.

### Постоянный кэш дистрибутивов и моделей

Windows-установщики (включая `Install-ShtabAI-RU.ps1`) предлагают отдельную папку
кэша, например `D:\Distributions\Shtab.AI-Cache`. Её можно задать параметром
`-CacheDir`. При повторной установке укажите ту же папку. Не размещайте кэш внутри
папки приложения или приложение внутри кэша.

* `archives` — Ubuntu WSL, Ollama Windows и библиотеки AMD. Перед использованием
  проверяется SHA256 из установщика или официального списка Ubuntu. Несовпавший
  файл скачивается заново; новую версию определяет её контрольная сумма.
* `qwen` — модели Windows Ollama. Перед установкой проверяется SHA256 каждого
  завершённого слоя. Ollama проверяет актуальный манифест `qwen3:4b` и получает
  только отсутствующие или изменившиеся слои.
* `whisper` — Whisper с метаданными Hugging Face. Проверяются текущая ревизия,
  SHA256 больших файлов и Git SHA1 остальных файлов. Повреждённые файлы
  заменяются, после загрузки снова проверяются хеши и пробное распознавание.

Кэш сохраняется после удаления приложения, вместе с моделями и незавершёнными
файлами загрузки моделей. Удаляется отдельно вручную, когда больше не нужен.
Данные пользователей, записи и база в кэш не попадают. Для проверки актуальных
версий и установки системных пакетов всё ещё нужен интернет. Проверка хешей и
копирование архивов занимают время, но повторной передачи больших файлов нет.
Не запускайте одновременно несколько установок с одним кэшем.

На Ubuntu модели сохраняются отдельно в `/var/cache/shtab-ai`; при прямом запуске
`install.sh` другой путь можно задать через `SHTAB_MODEL_CACHE`. Архивы Windows
на Ubuntu не используются.

Уже скачанные `ollama.zip`, `ollama-windows-amd64.zip`, `ollama-rocm.zip` или
образ Ubuntu можно положить прямо в выбранную папку кэша. Установщик проверит
их SHA256 и добавит в кэш, если содержимое соответствует ожидаемой версии.

### Докачка после прерывания

Запустите тот же установщик повторно. На Windows выбирайте **Установить** в том же
CMD-файле; удаление для продолжения не требуется. Зарегистрированная установка
продолжается в прежней папке с прежней версией приложения. На Ubuntu повторно
запустите актуальный `Install-ShtabAI-Ubuntu.sh`.

Уже работающая фоновая установка продолжает работу; повторный запуск подключает
индикаторы прогресса. После ошибки или перезагрузки возобновляется подготовка
компонентов с использованием кэша Docker и моделей. Проверки зависимостей и
сборки могут выполняться повторно. База данных, пользователи и настройки
сохраняются; готовый администратор повторно не создаётся.

В `Shtab.AI-Cache/archives` хранятся архивы Ubuntu и **программы Ollama**.
В `Shtab.AI-Cache/qwen` хранится **модель Qwen**, в `whisper` — Whisper.
Прерванные архивы сохраняются с суффиксом `.partial.part`; загрузчик запрашивает
оставшиеся байты и проверяет SHA256 всего файла перед использованием. Если
сервер не поддерживает Range, архив скачивается целиком. Повреждённые готовые
файлы заменяются. Для Whisper сохраняется закреплённая версия модели, чтобы
изменение версии на сервере не сбрасывало текущую докачку.

Для уже установленного Ubuntu доступно также:

```bash
sudo /opt/shtab-ai-021/shtabctl resume
sudo /opt/shtab-ai-021/shtabctl progress
```

При неполной конфигурации (утраченные пароли, диск или описание установки)
докачка останавливается с объяснением и сохраняет имеющиеся данные.
