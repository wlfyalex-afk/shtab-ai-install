# Штаб.AI — резервные копии и перенос совещаний

Одинаковые процедуры работают на Ubuntu и Windows/WSL2. Выбирайте формат по задаче:

| Формат | Что сохраняется | Что происходит при загрузке |
|---|---|---|
| Полная резервная копия | Все организации, пользователи, совещания, записи, результаты и конфигурация HTTPS | Текущая база и записи заменяются копией; сначала создаётся страховочная копия |
| Архив переноса одного совещания | Стенограммы, брифы, поручения, черновики, комментарии, связанные карточки исполнителей и, по выбору, аудио | Совещание добавляется в выбранную организацию; существующие данные и пользователи сохраняются |
| «Скачать ZIP» с документами | Отчёты и материалы совещания для чтения | Обратный импорт в базу не предусмотрен |

## Полная резервная копия

Дождитесь завершения загрузок, распознавания и подготовки результатов. На Ubuntu выполните:

```bash
sudo /opt/shtab-ai/shtabctl backup
```

На Windows откройте ярлык диспетчера → **2 — Управление в Ubuntu** → **5 — Создать резервную копию**. Также можно открыть это меню из PowerShell:

```powershell
wsl -d ShtabAI -u root --exec /opt/shtab-ai/shtabctl menu
```

После создания скрипт показывает полный путь копии. Это отдельная папка с датой, содержащая `manifest.json`, `database.dump`, `app-data.tar.gz` и `configuration.tar.gz`. Переносить нужно весь этот комплект. Модели из постоянного кэша в резервную копию не входят.

На Ubuntu стандартная папка копий — `/var/backups/shtab-ai`. При выборе другой папки приложения копии размещаются рядом с ней с суффиксом `-backups`. Например, для `/mnt/shtab-ai/shtabai` это `/mnt/shtab-ai/shtabai-backups`. На Windows диспетчер → **7 — Открыть папку резервных копий** показывает фактическую папку, выбранную при установке.

### Перенос полной копии из Ubuntu на Windows

Папка backups на Ubuntu закрыта от обычного пользователя. Не меняйте права на всю папку. Чтобы упаковать одну копию в домашнюю папку, введите её полный путь по запросу:

```bash
read -r -p 'Полный путь к конкретной папке копии: ' backup_dir
sudo test -f "$backup_dir/manifest.json" &&
sudo tar -czf "$HOME/shtab-backup.tar.gz" -C "$backup_dir" . &&
sudo chown "$(id -u):$(id -g)" "$HOME/shtab-backup.tar.gz" &&
chmod 600 "$HOME/shtab-backup.tar.gz"
```

Скопируйте `~/shtab-backup.tar.gz` на Windows и распакуйте в отдельную папку, например `D:\Transfer\Ubuntu-backup`. В ней непосредственно должны лежать `manifest.json` и три файла данных. Сам `.tar.gz` меню восстановления не принимает.

Откройте управление в Ubuntu через диспетчер Windows или приведённую выше команду WSL. Выберите **7 — Восстановить копию** и укажите путь к распакованной папке. Внутри WSL пример `D:\Transfer\Ubuntu-backup` записывается как `/mnt/d/Transfer/Ubuntu-backup`.

Скрипт проверяет контрольные суммы и совпадение схемы БД до изменения данных. При несовместимой схеме восстановление останавливается. Затем требуется подтверждение `RESTORE-SHTAB`; создаётся страховочная копия текущего состояния и восстанавливаются база и записи. Используйте версии приложения с одинаковой схемой.

После восстановления входите с логином и паролем из копии. Пароль подключения приложения к PostgreSQL и сетевые настройки текущей установки сохраняются, а сохранённые ключи HTTPS восстанавливаются. При смене удостоверяющего центра экспортируйте актуальный корневой сертификат и обновите доверие браузера; в диспетчере Windows это выполняется при возврате из меню Ubuntu.

Полные копии содержат закрытые данные и секреты приложения. Храните и передавайте их как резервные копии организации, не публикуйте на GitHub.

## Архив одного совещания

Этот способ подходит для передачи готового совещания с Ubuntu на Windows, с Windows на Ubuntu или между двумя компьютерами одной платформы. Не требуется доступ к папке backups или права администратора ОС. В приложении нужны права секретаря или администратора.

### Экспорт

1. Дождитесь завершения распознавания, выделения поручений и подготовки брифа.
2. Откройте **Совещания → нужное совещание → Перенести совещание**.
3. Оставьте флажок **Включить аудиозапись для прослушивания**, если аудио нужно на другом компьютере. Если аудио недоступно или слишком велико, снимите флажок: результаты можно перенести отдельно.
4. Нажмите **Скачать архив для переноса**. Браузер сохранит `shtab-meeting-transfer-<идентификатор>.zip` в выбранную вами папку загрузок.

В архив входят все стенограммы совещания, подготовленные брифы и статусы их утверждения, поручения и их текущие статусы/сроки, черновики, комментарии к поручениям, связанные карточки исполнителей и авторов проверки. Сохраняются завершённые задания анализа и их результаты. При включённом аудио переносится нормализованная звуковая дорожка для встроенного проигрывателя; исходный видеофайл и отдельные части исходной записи не включаются.

Учётные записи, пароли, телефонные контакты, история звонков, модели, сертификаты и настройки установки в этот архив не входят. Если нужны эти данные и полная история системы, используйте полную резервную копию.

### Импорт

1. Передайте ZIP на другой компьютер. Его не нужно распаковывать.
2. В приложении выберите организацию, в которую хотите добавить совещание. Секретарь работает в своей организации; администратор может переключить организацию.
3. Откройте **Совещания → Импорт совещания**.
4. Выберите ZIP, подтвердите добавление в текущую организацию и нажмите **Импортировать совещание**.
5. После импорта откроется обзор совещания. Стенограмма, бриф и поручения доступны сразу без повторного распознавания.

Все перенесённые сущности получают новые идентификаторы и сохраняют связи между собой. Связанные исполнители добавляются как отдельные карточки; совпадающие имена автоматически не объединяются, новые учётные записи для входа не создаются. Существующие совещания и пользователи не заменяются. Аудио доступно, если оно было включено в архив.

Повторный импорт той же исходной записи в ту же организацию отклоняется. При повреждении архива, неподдерживаемой версии формата или ошибке записи изменения отменяются. Проверяются состав файлов, контрольные суммы и связи результатов. При переносе аудио требуется свободное место на диске приложения для ZIP и распакованной дорожки. Максимальный размер ZIP — **2 ГиБ**, описания результатов — **32 МиБ**. Для больших записей можно передать результаты без аудио или воспользоваться полной резервной копией.

Импорт реализован в общей веб-части, поэтому формат одинаков на Windows и Ubuntu. На обеих установках должна быть версия приложения с поддержкой переноса совещаний. Обновление файлов установщика не обновляет автоматически уже работающий контейнер приложения.
